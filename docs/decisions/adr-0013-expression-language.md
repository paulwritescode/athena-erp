# ADR-0013: Expression language on cel-go for formulas, rules and filters
- **Status:** Proposed
- **Date:** 2026-11-19
- **Decision owner:** not assigned (awaiting project owner review)
- **Related decisions:** ADR-0005, ADR-0007, ADR-0010, ADR-0011, spec sections 3.3, 23.6, 24.4, roadmap phase P7 and user answer 4
## Context
Computed fields (formula, rollup), conditions on fields (`required_if`, `read_only_if`, `validate`, `depends_on`) and list filters need one small language. It must be side-effect free, always terminate, be type-checked when a Record Type is saved, never use binary floating point for money or quantities, and translate to a SQL predicate so that later row-level grants and reports can run in the database. Starlark (P9) is for sequenced logic and stays separate.
## Options considered
1. **A hand-written mini-language.** Full control of types and errors, no dependency. Cost: a parser, a type checker and their tests, all of which already exist in a maintained form.
2. **cel-go (chosen).** Google's Common Expression Language for Go. Non-Turing-complete by design, a parser with size and recursion limits, a type checker that reports errors with columns, and a typed AST that the SQL translator walks. Cost: a dependency (`cel.dev/cel-go` v0.33.4, which pulls `cel.dev/expr`, `github.com/antlr4-go/antlr/v4` and `golang.org/x/exp`), and CEL has no exact decimal type, so it is added here.
3. **Starlark for everything.** Rejected: it is a programming language (loops, functions), so termination and SQL translation are not guaranteed.
## Why cel-go fits this runtime
- Pure Go, no cgo, no code generation, no network at run time; the single Go binary stays a single binary (ADR-0001). It builds with the repository's Go toolchain and adds no process.
- The module path moved from `github.com/google/cel-go` to `cel.dev/cel-go`; the repository uses the new path.
- Evaluation is deterministic and has no I/O. `today()` is not read from a clock inside the library: the caller injects the date.
## Decision (proposed)
- **Package.** `internal/expr` owns the language. It never touches the database. `internal/server/expressions.go` maps Record Types to variables and runs expressions inside the write transaction.
- **A restricted subset.** CEL's standard library is not loaded except `&&`, `||`, `!` and `?:`. Macros are off, so there are no loops (`exists`, `map`, `filter`). Floating point, unsigned and byte literals, lists, maps and message construction are rejected. Expressions are at most 2000 characters (stored attributes at most 1000) with a parser recursion limit of 32, so evaluation cost is bounded by expression size.
- **Types.** `bool`, `int`, `string`, `date` (a CEL timestamp at UTC midnight), `decimal` and `money`, both backed by `internal/types` (ADR-0007). A `decimal` is exact (`dec("1.50")`, scale ignored in comparisons). A `money` carries its currency and minor-unit exponent; adding amounts of different currencies is an error. `money * number` rounds once, to the currency's own exponent and rounding mode, and drops the difference (postings record it in P12). Division is explicit: `div(a, b, places)` rounds half up; there is no `/`. `round(decimal, places)` is half up.
- **Null.** Arithmetic with null is null. An ordering comparison (`<`, `<=`, `>`, `>=`) with null is false. `==` and `!=` treat null as a value that equals only null (`x == null` tests for empty), which is SQL's `<=>`. A null checkbox reads as false. `coalesce(a, b)` picks the first non-null.
- **Scope.** `doc.<field>` for every field and for `revision`, `owner`, `created_by`, `modified_by`, and for submittable documents `docstate` and `name`. A child Record Type's numeric and money fields are lists named `doc.<child>.<field>`, read only by `sum`, `min`, `max` and `count`; they make a **rollup**. `today()`, `add_days`, `add_months`, `lower`, `startsWith`, `matches` (RE2), `amount`, `currency`, `dec`, `money` complete the allow-list. `user`, `parent`, `row`, `action`, `ctx`, `setting()`, `period_of` and `in` are not built: they belong to P8, P11 and later phases.
- **Field attributes** (`RecordTypeField`, JSON in the Record Type definition, no table change). `formula` is calculated by the kernel on create, on update and when a child Record changes, stored in the field's own column, in dependency order. Clients cannot set it (the server rejects a value), a formula cannot use `today()` (its stored result must be reproducible), cannot be set-once, no-copy or have a default, and a cycle (including a field reading itself) is rejected when the Record Type is saved. A child Record's change recalculates its parent's formulas in the same transaction, without changing the parent's revision, and appends a `recalculated` Audit Log row. `required_if` and `validate` are checked on every create and update against the final values (`validate` is skipped for an empty field). `read_only_if` blocks changing the field while it is true for the stored Record (updates only). `depends_on` is a display hint that the server does not enforce.
- **Save-time checks.** Every expression is parsed and type-checked when a Record Type is saved. The result kind must fit the field (numbers need `decimal` or `int`, money needs `money` in the field's currency and scale, dates `date`, checkboxes `bool`, text `string`). Saving a child Record Type re-checks its parent's expressions with the new definition, so a change that would break a rollup is refused.
- **Changing a formula** adds a non-destructive `recalculate` step to the save plan and recalculates every stored Record (one transaction each, idempotent, resumed after a crash like the rest of the save). A changed child formula also recalculates its parent's rollups.
- **SQL translation.** `Program.Translate` turns a boolean expression into a predicate through five small `store.Dialect` methods (`NullSafeEqual`, `BinaryString`, `DecimalParam`, `DateParam`, and the existing quoting). Strings compare with `utf8mb4_nopad_bin` (the tables use `utf8mb4_unicode_ci`, which would ignore case, accents and trailing spaces), decimals bind as `DECIMAL(65,30)` so no comparison goes through a float, comparisons are wrapped as `COALESCE(x, FALSE)` so `NOT` over a null comparison matches the in-memory result. Constant parts (`dec`, `money`, `today()`, `add_days` of constants) are folded in Go with the same helpers the evaluator uses. Not translatable (the caller gets a clear error): lists, `lower`, `matches`, text joining, `div`, money multiplication, `add_days` of a column. `RecordService.ListRecords` takes a `filter`; the invariant test runs 36 expressions over rows with nulls both ways and compares the rows.
- **API.** `RecordService.PreviewRecord` calculates formulas and field states for unsaved values (the desk uses it as a display hint; the server calculates again on save) and `RecordService.EvaluateExpression` checks or evaluates one expression. CLI: `athena expressions check|eval|preview` and `athena records list --filter`. Spans for the new operations carry the operation, Record Type key, request ID and outcome only; the expression text and values are never attributes.
- **Not built.** Lookup fields (`fetch_from`), `hidden_if`, `default_from`, `user.*` and scopes, `setting()`, `period_of`, expression-based naming, translating `add_days` of a column, caching compiled expressions across requests, and a TypeScript evaluator (the desk asks the server).
## Consequences
- One new direct dependency tree. Compile cost per write is the parse and check of the Record Type's expressions (no cache yet), paid only by Record Types that use expressions.
- The language is smaller than CEL on purpose: users cannot write `1.5`, `/`, `size()`, `in [...]` or comprehensions. Adding any of them later is additive.
- PostgreSQL is untested (ADR-0005). The four new dialect methods have no second implementation.
## Revisit when
P8 (the `user` and permission-level scopes and row grants through `Translate`), P9 (Starlark reading expression results), P11 (`ctx`, `period_of`), P14 (the report query compiler may reuse `Translate`), a PostgreSQL implementation.
